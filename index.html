Archetypes & Clustering (GPT, By Site)
What is an Archetype?
An archetype is a grouping of sites that share the same capability profile and can be configured from a single template build. Each archetype requires one template build effort — additional sites in the same archetype are delivered as rollout waves.
Sites are automatically grouped into archetypes based on their scored capabilities. Sites whose capabilities are fully covered by an existing archetype (and have ≤ 4 Advanced capabilities) roll into that archetype's waves instead of getting their own template.
Rollout Waves
Each rollout wave is 20 weeks. The Connect phase of a rollout wave begins at the start of the prior engagement's Close phase (4-week overlap). Wave capacity limits apply across the whole engagement — not per archetype. Ideally no rollout wave should exceed 4 sites total across all archetypes.
Contingency & Role Exclusion
Contingency is set per archetype — useful when risk profiles differ across sites or when quoting fixed fee. A 5% readiness contingency is suggested automatically when low data or scheduling maturity is detected.

Roles can be excluded per archetype from the resource table in the Estimate Summary. Excluded roles are removed from hours and the Gantt for that archetype only.

Tier Capability Matrix

Use this matrix to identify which tier best describes each site. A site's tier is determined by its highest-complexity requirement.

Foundational
Standard scheduling with basic routing and capacity. Single operation, no parallel processing, no managed constraints.
Intermediate
More complex routing and capacity. Multi-operation, parallel processing, changeovers, or multi-level BoMs present.
Advanced
High-complexity requirements. Managed constraints, cross-site dependencies, pegging, batching, or skilled labor.
